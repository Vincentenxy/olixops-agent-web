# 前端开发与接口契约

本文约定前端实现边界。运行命令、现有页面与配置见 [README](../README.md)，布局及交互细则见 [UI 开发规范](ui-development-standards.md)，待接入能力见 [todo](../todo.md)。

## 架构与职责

`olixops-agent-web` 使用 React、TypeScript、Vite 构建 SPA；React Router 负责页面路由，TanStack Query 管理服务端数据，Ant Design 提供控制台组件。后端 `olixops-agent` 独立提供 FastAPI API、Agent 编排与 Terraform Worker。

这是需要登录、持续查看任务的操作控制台，当前没有搜索引擎索引或服务端渲染页面的需求。SPA 能把静态资源交付与后端任务执行分开；后续出现明确 SSR 需求时再评估相应框架。

- 页面组合业务组件，API 访问集中封装；复用已有模块，避免在组件中分散拼接请求、解析统一响应或处理认证。
- 表单编辑、面板展开等临时交互由局部状态管理；服务端数据及其 loading、error、刷新与缓存由 TanStack Query 管理。
- 导航位置由 URL 表达。跨页面需要复用的客户端状态具有明确的持久化位置与生命周期。
- 输入、响应和跨模块数据使用明确 TypeScript 类型；API 响应在运行时检查必要结构。类型断言不能代替对外部数据的检查。
- Ant Design 的主题与通用尺寸集中配置；图标优先采用项目现有库，紧凑图标按钮遵守 UI 规范中的统一尺寸与语义状态。
- 长任务由后端管理；关闭页面、请求取消或网络中断不能被前端解释为部署取消或部署失败。

## 后端接口契约

接口约定同步自后端 `olixops-agent/README.md`，同步日期：2026-09-08。后端 README 是协议来源；联调时核对同版本的后端文档和实际 OpenAPI，协议变化同时更新前端封装与本文。

### 路径与方法

- 业务路径使用 `/api/v1/...`；`/api/v1/pub/...` 是显式注册的公开接口，其余业务接口携带 `Authorization: Bearer <token>`。
- 业务方法只使用 GET / POST：带参数使用 POST，不带参数或分享链接使用 GET；GET 保持只读，部署和取消使用 POST。
- CORS 的 OPTIONS 预检由服务端/网关处理。前端跨域配置必须与实际 API 暴露方式一致。
- 当前联调入口为 `GET /api/v1/pub/health`。健康检查成功只证明 API 可访问，不代表用户认证、MCP 或 Terraform 已就绪。

### 统一 JSON 响应

```json
{ "code": 0, "msg": "", "data": {} }
```

| code       | 含义                                       | 前端处理                                   |
| ---------- | ------------------------------------------ | ------------------------------------------ |
| `0`        | 成功                                       | 使用响应中的 `data`                        |
| `-1`       | 通用业务失败                               | 展示业务失败，不作为成功数据缓存           |
| `1 ~ 1000` | 系统预留失败码；600 以内与 HTTP 状态码一致 | 按系统/HTTP 错误处理，不定义自己的业务含义 |
| `10000+`   | 业务失败码                                 | 按已约定的业务含义呈现并保留错误信息       |

- HTTP 200 仍需检查 `code`；非零 `code` 是失败结果。
- HTTP 400 / 401 / 403 / 404 / 405 / 422 / 500 等错误使用对应状态码，body 的 `code` 等于 HTTP 状态码，`msg` 为标准状态文本，`data` 为 `null`。
- 网络失败、超时、非 JSON 响应和不符合 envelope 的响应应呈现为连接或协议错误；网关 HTML 错误页不能被解析成任务状态。
- 后端业务错误信息与表单/操作区域关联展示；加载、禁用、成功、失败保持可区分。
- 部署提交等有副作用的请求，不因重试或刷新重复执行；是否重试取决于后端幂等契约。

### 认证与凭据

- 后端以 RSA 公钥验证 JWT，算法允许列表为 RS256 / RS384 / RS512；前端解析 claims 仅能用于展示，不能据此判断服务端已认证。
- 后端从 `staffuserid` 和 `name` 解析用户信息。前端需要的用户响应字段由实际 API 显式定义，不依赖原始 token 或 Cookie 回显。
- 缺少/无效/过期 token 返回统一 HTTP 401；身份有效但无资源权限返回 HTTP 403，两种情况分别处理。
- 当前 API 封装通过内存 token provider 为受保护接口读取 Bearer token，未接入真实登录来源；公开接口不附加 token。登录、刷新、退出和后续 token 存储策略待真实身份系统接入后确定。
- 浏览器包、`VITE_*` 变量和构建产物均可被用户读取，仅放公开配置；云凭据、JWT 签名密钥和 Terraform 执行凭据由后端管理。
- 当前请求使用 `credentials: 'omit'`，不发送 Cookie。是否改为携带 Cookie 由最终身份方案决定；启用跨域 Cookie 时同步配置具体允许的 Origin、credentials 和相关服务端行为。

### 请求追踪

- 当前客户端为请求生成 32 位十六进制 `X-Request-Id`；后端透传已有值或在缺失时生成，并在响应头回写。
- 当前 API 封装在错误信息中保留响应头的请求 ID，方便将前端错误与服务端日志关联；日志、错误面板和遥测避开 token、Cookie 和敏感配置。
- 跨域读取响应头时，需要后端/网关显式暴露 `X-Request-Id`。任务关联使用后端返回的 `task_id`，请求 ID 与任务 ID 各自保留。

## 异步任务与状态呈现

- 需求草稿是客户端编辑内容；只有后端返回已创建的任务，才能进入真实任务列表。
- 后端暂未提供任务接口时，展示未连接状态或空态；空列表不能推断为任务查询成功。
- 任务状态、步骤、日志游标与重连方式以真实任务协议为准；轮询或 SSE 的选择见 todo。
- 计划审核状态绑定具体 Terraform plan；是否需要审核按环境授权策略决定。前端只呈现服务端权限和动作，不自行决定 apply 授权。
- 展示部署成功需要后端确认实际结果；取消请求发出后，应等待后端返回取消或最终状态。
