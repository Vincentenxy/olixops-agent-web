# UI 开发规范

来源：本地技能 `ui-development-standards/references/standards.md`。同步日期：2026-09-08。

本文是随仓库维护的完整规范副本，开发和评审直接使用本文件，无需安装个人技能。同步时保留适用细则，并核对项目已有组件与交互。三栏示例已改为通用命名，未改变布局规则。

适用于 DevOps 控制台、管理后台、配置编辑器、列表/详情工作流和内部工具。以下内容是默认规则，不代表可以顺带重做无关页面。

## 1. 信息架构

- 首屏直接呈现工作区，避免营销式构图、超大标题、装饰性面板和过量卡片。
- 采用紧凑但有序的布局、清晰对齐、克制配色和可预测导航。
- 不在卡片中继续嵌套卡片。卡片只用于重复项、弹框或确实需要边界的工具。
- 标题字号与容器匹配，紧凑面板使用紧凑标题。
- 控件靠近其操作的数据，不为互不相关的面板创建一个全局工具栏。

## 2. 面板工具栏

- 每个可独立操作的面板拥有自己的标题和工具栏。
- 改变面板数据上下文的选择器放左侧，例如版本、环境、范围和分支。
- 命令及操作图标全部放右侧，例如比对、视图切换、编辑、保存、取消、刷新、全屏和新建。
- 相邻面板工具栏保持同一基线、稳定高度、统一间距和清晰边界。
- 选择器区域允许收缩，操作区不收缩。窄宽度下可以缩短或换行选择器，但操作按钮不得重叠或跑出所属面板。
- 分隔线或下划线应覆盖完整工具栏区域，不能只停留在标题或选择器下方。

三栏配置编辑器采用以下布局语法：

```text
模板配置    [版本选择器 ...............]  [帮助] [视图] [比对] [编辑]
环境配置    [版本选择器 ...............]  [帮助] [视图] [比对] [编辑]
变量列表    [范围/搜索 ................]  [帮助] [刷新]
```

## 3. 命令与图标

- 使用产品已有图标库；存在常见库图标时不手绘。
- 紧凑命令使用熟悉符号：铅笔表示编辑，对号表示保存/确认，叉号表示取消，循环箭头表示刷新，展开表示全屏，分栏/diff 图标表示版本比对。
- 当上下文已经说明创建对象时，紧凑的新建操作使用蓝色圆圈加号。
- 语义明确的常见图标不需要 hover 文案；版本比对、业务模式切换等不熟悉或有歧义的动作需要 tooltip。
- 即使不显示 tooltip，纯图标按钮也必须保留 `aria-label` 等无障碍名称。
- 操作顺序保持稳定。进入编辑态后，在原操作区用“保存、取消”替换“编辑”，不要移动整条工具栏。
- 加载和禁用状态不能改变控件尺寸或推动相邻内容。

### 统一图标按钮与选中状态

- 同一工具栏内所有可点击的小图标使用相同尺寸的圆形描边按钮，图标居中；不能混用裸图标、无边框 text 按钮和不同大小的默认按钮。优先复用页面级 `IconButton` 或统一样式类，避免逐个写行内样式。
- 普通命令和未选中的切换按钮默认使用白色或透明背景、中性色图标及边框；确认、取消等具有明确结果语义的命令使用对应的语义色；选中的切换按钮使用蓝色图标、蓝色边框和克制的浅蓝底色。
- 保存、确认、应用、对号等肯定语义的纯图标按钮使用绿色图标与绿色边框；取消、放弃、叉号等否定语义的纯图标按钮使用红色图标与红色边框。颜色应表达操作结果，不按图标形状机械套用：退出全屏、关闭只读预览等非取消语义的叉号不使用红色。
- 只有具有持续开关或视图状态的按钮才使用选中态，例如解析视图、面板显示、全屏和展示模式。刷新、编辑、保存、取消、帮助、版本比对等一次性命令不使用蓝色选中态，避免制造“仍然选中”的错觉。
- 选中态不能只依赖颜色：切换按钮同步设置 `aria-pressed`，并在适合时切换图标。hover 只提供即时反馈，不能与持久选中态相同；disabled 使用低对比度且不能保留选中蓝色。
- 圆形容器只用于可点击按钮。树形折叠箭头、输入框前缀、告警或状态标识、文本内图标不添加外圈。
- loading、权限禁用以及图标切换前后必须保持按钮外径、边框和工具栏占位不变。

## 4. 间距与对齐

- 选择器与操作区之间保留清晰且一致的间距；版本选择器不能夹在编辑/保存按钮之间。
- 标签、值、表格单元格、错误和滚动消息默认按阅读方向左对齐，纯数字内容除外。
- 编辑器、棋盘、工具栏、图标按钮、计数器等固定格式元素使用稳定尺寸。
- 长标签和值应换行、可查看完整值的截断，或进入受限滚动区，不能与相邻控件重叠。
- 用克制的边框和底色表达结构，装饰不能压过数据。

## 5. 滚动与视口归属

- 面板内容很长时页面外壳保持固定；编辑器、表格、秘钥列表和错误列表在各自有边界的区域内滚动。
- 面板内定位或程序化滚动只能调整该面板的滚动容器，不能推动 `document.body`。
- 除非用途明确，否则避免嵌套滚动；验证滚轮、触控板、键盘和程序化滚动。
- 全屏视图必须始终能退出并访问主要操作，同时不能制造页面级溢出。

## 6. 编辑与文本交互

- 高亮、装饰层和点击处理不能阻止光标定位、拖选、双击选词、键盘选择或复制。
- Monaco 等编辑器优先使用不拦截指针事件的 decoration；触发定位前应区分单击与双击。
- 除非需求明确替换，否则保留撤销/重做和编辑器原生右键菜单。
- 保存与取消结果必须确定：取消恢复已加载内容；保存展示加载、成功和失败，不能静默丢失编辑。

## 7. 关联数据高亮

- 在编辑器或列表间关联同一逻辑变量时，同时高亮所有来源位置和解析后的目标。
- 成功关联使用整行淡绿色底色，并配合克制的定位标记。
- 找不到目标时使用明确不同的未解析样式和简洁的“无法解析”提示。
- 高亮限制在各自面板内并保留原生文本交互；同一变量多处出现时全部体现。

## 8. 列表、详情与模式

- 将每个列表模式视为独立的信息契约，只显示该模式相关的列和筛选项。
- 模式专属筛选条件按模式展示，例如“待我发布”不应出现在无此语义的模式中。
- 模式切换入口保持稳定；用户通常长期使用某一模式时，将该选择持久化到本地。
- 打开层级结构时默认选中最小有效上下文。例如必须有系统时选中第一个系统，但流程不要求模块时不要自动选模块。
- 详情编辑态只把可编辑值切换成控件；身份信息和审计字段保持明显只读。

## 9. 错误、加载与空状态

- 校验或发布检查错误应靠近其阻止的操作，左对齐；多条消息使用有边界的滚动列表。
- 紧凑错误区无法合理展示全部消息时，提供展开或全屏查看。
- 异步检查结果返回前，依赖该结果的操作保持 loading 或禁用。
- 空状态使用标准组件和附近上下文说明，不创建大型说明面板。

## 10. 视觉验收

完成前在典型桌面和窄宽度视口检查：

- 无重叠、裁切、异常换行和页面级溢出；
- 每个面板的选择器仍在左侧，命令仍在右侧；
- 相邻面板的工具栏和编辑器边界对齐；
- 文本选择、双击、复制、编辑、保存/取消、加载和禁用状态仍可用；
- 定位滚动仍限制在所属面板；
- 需要持久化的视图选择在刷新后正确恢复。
